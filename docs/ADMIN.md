# 🛡️ لوحة الإدارة، المستخدمين والصلاحيات

اللوحة على `/admin` — واجهة عربية RTL جوّه نفس المشروع، شغالة على قاعدة بيانات SQLite حقيقية
(مش مصفوفات في الذاكرة زي الأول).

## 1) التشغيل في 30 ثانية

```bash
npm install
npm run dev          # http://localhost:3000/admin
```

أول تشغيل بيعمل الملف `data/gym.db` لوحده (ميجريشن + بيانات عرض). حسابات وضع العرض:

| الحساب | الدور | كلمة السر |
| --- | --- | --- |
| `owner@fitzone.pro` | المدير العام | `Owner#Fit2026` |
| `manager@fitzone.pro` | مدير الفرع | `Manager#Fit2026` |
| `coach.ahmed@fitzone.pro` · `coach.mohamed@…` · `coach.sara@…` | كوتش | `Coach#Fit2026` |
| `reception@fitzone.pro` | استقبال | `Front#Fit2026` |

> الحسابات دي بتتزرع بس لما `DEMO_SEED=1` (الافتراضي في التطوير).
> **في الإنتاج** حط `DEMO_SEED=0` و`SEED_OWNER_EMAIL` + `SEED_OWNER_PASSWORD`،
> ولو سيبت كلمة السر فاضية هتتولّد عشوائية وتتطبع في لوج السيرفر **مرة واحدة**
> والحساب هيتطلب منه يغيّرها أول دخول.

## 2) الأدوار والصلاحيات

مصدر الحقيقة الوحيد: [`app/lib/auth/roles.ts`](../app/lib/auth/roles.ts) — والواجهة بتخفي الأزرار
حسب الصلاحية، **بس المنع الحقيقي على السيرفر** في `authorize()`.

| | المدير العام | مدير الفرع | كوتش | استقبال |
| --- | :---: | :---: | :---: | :---: |
| يشوف كل الاشتراكات | ✅ | ✅ | ❌ (بتوعه بس) | ✅ |
| يشوف الإيراد | ✅ | ✅ | ❌ | ❌ |
| تجميد / استئناف | ✅ | ✅ | ❌ | ❌ |
| **إلغاء اشتراك** | ✅ | ✅ | ❌ | ❌ |
| **حذف اشتراك نهائي** | ✅ | ❌ | ❌ | ❌ |
| إسناد كوتش لعضو | ✅ | ✅ | ❌ | ❌ |
| الحجوزات (عرض/تعديل) | ✅ | ✅ | بتاعته بس | ✅ |
| حذف حجز | ✅ | ✅ | ❌ | ❌ |
| إدارة المستخدمين | ✅ | ❌ (عرض بس) | ❌ | ❌ |
| سجل العمليات | ✅ | ✅ | ❌ | ❌ |

قواعد إضافية متزرعة في السيرفر:

- مدير الفرع **ما يقدرش** يلمس حساب مدير عام (لا تعديل ولا حذف ولا ترقية).
- مفيش حد يقدر يوقف أو يمسح حسابه هو، ولا آخر مدير عام في النظام.
- تغيير دور/كلمة سر/تعطيل حساب = **كل جلسات المستخدم ده بتموت في نفس اللحظة**.
- الكوتش بيشوف أعضاءه بفلترة على مستوى الـ SQL (`WHERE coach_id = ?`) — مش إخفاء في الواجهة.
- تليفون العضو بيتخفي جزئيًا (`010•••••78`) للأدوار اللي مش محتاجاه كامل.

## 3) قاعدة البيانات

```
app/lib/db/
  index.ts          الاتصال + الميجريشن (user_version) + الفولباك لقاعدة في الذاكرة
  seed.ts           المدير العام + بيانات العرض
  users.ts          المستخدمون + قفل المحاولات الفاشلة
  subscriptions.ts  الاشتراكات + الإحصائيات + انتهاء الصلاحية التلقائي
  bookings.ts       الحجوزات
  audit.ts          سجل العمليات
  rate-limit.ts     حاجز الطلبات (login / bookings / OTP)
```

الجداول: `users` · `sessions` · `subscriptions` · `bookings` · `audit_log` · `rate_limits`.

المتغيرات:

| المتغير | الافتراضي | يعمل إيه |
| --- | --- | --- |
| `DATABASE_PATH` | `data/gym.db` | مسار ملف SQLite · `:memory:` للاختبارات |
| `DEMO_SEED` | `1` خارج الإنتاج | زرع حسابات وبيانات العرض |
| `SEED_OWNER_EMAIL` / `SEED_OWNER_PASSWORD` | — | حساب المدير العام الأول |

**للانتقال لـ MySQL/Postgres**: بدّل ملفات `app/lib/db/*` بس — الـ routes والواجهة
بيتكلموا مع الدوال دي (`listSubscriptions`, `setSubscriptionStatus`, …) مش مع SQL.

## 4) دورة حياة الجلسة

1. `POST /api/admin/auth/login` → توكن 32 بايت في كوكي `fz_session` (HttpOnly · SameSite=Strict · Secure على https).
   المخزّن في الداتابيز هو **sha256 للتوكن** مش التوكن نفسه.
2. مع الكوكي بيتبعت توكن CSRF في كوكي `fz_csrf` (مقروء للجافاسكريبت) — وكل طلب
   POST/PATCH/DELETE لازم يبعته في هيدر `x-csrf-token`.
3. الجلسة بتنتهي بعد **ساعة خمول** (بتتجدد مع الاستخدام) وبسقف مطلق **12 ساعة**.
4. الخروج / تغيير كلمة السر / تعطيل الحساب = الجلسة بتتمسح من الجدول فورًا.
